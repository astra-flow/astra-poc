# 敏捷软件开发 AI 应用 Token 资源包预算测算说明

## 1. 文档目的

本文档为 AI 大模型 Token 资源包采购申请的费用测算附件，说明预算金额的测算依据、数据来源与计算逻辑，确保预算可追溯、可审计、逻辑自洽。

## 2. 采购背景

为支撑敏捷软件开发全流程的 AI 赋能，研发团队已在 PRD 生成、架构图生成、代码生成、自动化测试脚本、基础软件开发、日志分析等 6 类场景中广泛使用 AI 大模型。本次采购旨在通过预付费 Token 资源包方式统一保障各场景的模型调用额度，降低单位调用成本，避免按量付费的不可控风险。

## 4. 测算方法

### 4.1 方法论选择

调研表包含两类数据，可信度不同：

| 数据类型 | 可信度 | 依据 |
|---------|:------:|------|
| 费用数据（人均月费用 × 使用人数 = 月总费用） | 高 | 62 条应用产品记录经校验全部自洽，0 条偏差 |
| Token 消耗量数据 | 低 | 反推单价远低于市场价 16-108 倍，存在量纲错误或填报不规范 |

基于上述校验结果，本次测算采用**费用主线法**：以可信的费用数据为基准，结合市场真实单价反推 Token 消耗量，实现费用与 Token 双向自洽。

### 4.2 计算公式

**加权单价**（假设输入:输出 Token 比 = 3:1）：

$$
P_{加权} = \frac{P_{输入} \times 3 + P_{输出} \times 1}{4}
$$

**月 Token 消耗量**：

$$
Q_{月} = \frac{F_{月}}{P_{加权}}
$$

**年度预算**：

$$
B_{年} = F_{月} \times 12 \times \alpha
$$

其中 $\alpha$ 为波动系数，取值 1.15。

### 4.3 波动系数说明

波动系数 1.15 用于覆盖三方面上行波动：

| 波动来源 | 说明 |
|---------|------|
| 业务自然增长 | 调用频次随业务发展提升 |
| 采用率提升 | AI 工具从"部分使用"向"全面使用"渗透深化 |
| 调试消耗 | Agent 多轮迭代、Prompt 调优、失败重试产生的额外消耗 |

该系数取保守值，基于调研数据已较全面覆盖现有场景的判断。

### 4.4 测算方式对比与选择依据

为验证费用主线法的合理性，对两种测算方式进行了对比：

| 测算方式 | 年预算 | 说明 |
|---------|:------:|------|
| 费用主线法（采用） | 314.5 万元 | 以调研表费用数据为基准 |
| Token 主线法（弃用） | 20,749 万元 | 按调研表填报 Token × 市场单价 |

Token 主线法得出 2.07 亿的荒谬结论，反证调研表 Token 数据虚高 16-108 倍。根因分析：

| 模型族 | 市场加权单价（元/百万） | 填报 Token 反推单价 | 虚高倍数 |
|--------|:--------------------:|:-----------------:|:--------:|
| DeepSeek-V4 | 18.00 | 0.31 | 57x |
| GLM-5.2 | 18.00 | 0.17 | 108x |
| Qwen3-Plus | 4.20 | 0.18 | 23x |

可能原因：量纲混淆（字符数当 Token 填）、估算粗放、包含失败请求等。因此 Token 数据不能直接用于预算测算。

## 9. 假设与约束

1. **输入输出比假设**：加权单价按输入:输出 = 3:1 计算，基于典型业务场景。实际比例可能因场景而异，但对费用主线测算无影响（费用数据为调研实测值）。

2. **GLM-5.2 单价**：采用智谱官方定价，实际采购以正式报价单为准。

3. **Qwen3 档位**：调研表未细分 Qwen3 子型号，统一按 Plus 档（均衡型）计价，该档位为代码生成场景的主流选择。

4. **波动系数**：1.15 为保守估计，若业务处于快速扩张期，建议上调至 1.3。

5. **覆盖人数**：按 400 人测算，实际使用人数以调研表统计为准（应用产品 163 人 + 基础软件 127 人 = 290 人），400 人含未覆盖人员的扩展余量。

6. **费用口径**：PRD 生成场景费用仅含纯 API 调用费，ArkClaw 席位费和 Coding Plan 费用已剔除，走单独采购流程。
