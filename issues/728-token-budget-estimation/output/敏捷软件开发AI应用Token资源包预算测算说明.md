# 敏捷软件开发 AI 应用 Token 资源包预算测算说明

## 1. 文档目的

本文档为 AI 大模型 Token 资源包采购申请的费用测算附件，说明预算金额的测算依据、数据来源与计算逻辑，确保预算可追溯、可审计、逻辑自洽。

## 2. 采购背景

为支撑敏捷软件开发全流程的 AI 赋能，研发团队已在 PRD 生成、架构图生成、代码生成、自动化测试脚本、基础软件开发、日志分析等 6 类场景中广泛使用 AI 大模型。本次采购旨在通过预付费 Token 资源包或框架协议方式统一保障各场景的模型调用额度。

## 4. 测算方法

### 4.1 方法论选择

调研表包含两类数据，可信度不同：

| 数据类型 | 可信度 | 依据 |
|---------|:------:|------|
| 费用数据（人均月费用 × 使用人数 = 月总费用） | 高 | 62 条应用产品记录经校验全部自洽，0 条偏差 |
| Token 消耗量数据 | 低 | 反推单价远低于官方刊例价 16-108 倍，存在量纲错误或填报不规范 |

基于上述校验结果，本次测算采用**费用主线法**：以可信的费用数据为基准，结合官方刊例价反推 Token 消耗量，作为规模参考。

### 4.2 计算公式

**加权单价**（假设输入:输出 = 3:1，缓存命中率 = 50%）：

$$
P_{加权} = \frac{(P_{命中} \times 0.5 + P_{未命中} \times 0.5) \times 3 + P_{输出} \times 1}{4}
$$

**月 Token 量**：

$$
Q_{月}(\text{百万}) = \frac{F_{月}}{P_{加权}}
$$

**年度预算**：

$$
B_{年} = F_{月} \times 12 \times \alpha
$$

其中 $\alpha$ 为波动系数，取值 1.15。

**单位换算**（已验证）：
- 1 百万 = 1,000,000 个 Token
- 1 亿 = 100,000,000 个 Token = **100 百万**
- 百万 Token ÷ 100 = 亿 Token

### 4.3 波动系数说明

波动系数 1.15 用于覆盖三方面上行波动：

| 波动来源 | 说明 |
|---------|------|
| 业务自然增长 | 调用频次随业务发展提升 |
| 采用率提升 | AI 工具从"部分使用"向"全面使用"渗透深化 |
| 调试消耗 | Agent 多轮迭代、Prompt 调优、失败重试产生的额外消耗 |

### 4.4 采购方式建议

建议按金额签框架协议，不按 Token 量签，理由：

1. **主力模型价格浮动**：随新模型推出会变化
2. **新模型价格未知**：新模型我们肯定要用，但价格无法预判
3. **各家计价不一**：各家 Token 计价方式不同，且资源包有折扣，按 Token 量签不可控

## 8. 假设与约束

1. **输入输出比假设**：加权单价按输入:输出 = 3:1 计算，缓存命中率 50%，基于典型业务场景。实际比例可能因场景而异，但对费用主线测算无影响（费用数据为调研实测值）。

2. **GLM-5.2 单价**：假设与 DeepSeek-V4-Pro 同档，实际采购以智谱正式报价单为准。

3. **波动系数**：1.15 为保守估计，若业务处于快速扩张期，建议上调至 1.3。

4. **覆盖人数**：按 400 人测算（目前 389 人，7 月入职 11 人），调研表实际覆盖 290 人，400 人含未覆盖人员的扩展余量。

5. **费用口径**：PRD 生成场景费用仅含纯 API 调用费，ArkClaw 席位费和 Coding Plan 费用已剔除，走单独采购流程。

6. **Qwen3-Plus 折算**：原调研表中 Qwen3-Plus 用量（月费用 65,067 元）已折算到 DeepSeek-V4-Flash。折算后费用金额不变，但 Token 量按 Flash 单价反推（Flash 单价更低，Token 量更大）。

7. **Token 量性质**：本文档 Token 量均按官方刊例价反推，作为规模参考。实际采购建议按金额签框架协议，不按 Token 量签（理由见 4.4 节）。
