三、模块详解

开场：为什么你明明会用 AI，但做不出好产品？（30min）

核心问题：从"手搓 HTML"到"交付可维护产品"，中间缺了什么？

场景普通用法智能体工程用法
写一个直播数据看板 一次 prompt 出代码 → 复制粘贴 → 跑起来就完 先写 spec → AI 生成 → 审查 → 迭代 → 沉淀为可复用模板
一周后需求变更 重新写 prompt，AI 忘了之前的上下文 有 Skill 文件记录上下文，AI 秒懂之前做了什么
同事也想用 发一段 prompt 给他，效果不一样 发一个 Skill 文件 + 使用说明，效果一致

模块一：Vibe Coding 系统性方法（1.5h）

定位：学员的"舒适区"起点，但需要系统化。

1.1 结构化 Prompt 工程（30min）

Prompt 五要素模板
[角色] 你是一个资深前端工程师
[上下文] 我们正在为一个电商运营团队开发直播数据看板
[任务] 创建一个 React 组件，展示单场直播的核心指标
[约束] 使用 Tailwind CSS，数据从 props 传入，支持移动端响应式
[输出格式] 完整的 .tsx 文件，含类型定义和注释

练习：用课前作业重新做一遍，对比代码质量差异。

1.2 多轮对话管理（20min）

  • 何时开新对话：话题切换超过 50% 时
  • 何时继续对话：在同一功能上迭代时
  • 上下文抢救技巧：让 AI 输出"当前项目状态摘要"，粘贴到新对话
  • Checkpoint 策略：每完成一个独立功能，git commit 或复制代码快照

1.3 工具链选型（20min）

路径 A：零部署路径（非技术岗首选）

Bolt.new / Lovable → 描述需求 → AI 生成全栈应用 → 一键部署 → 可分享链接

路径 B：专业开发路径（有代码基础可选）

Cursor / Windsurf → 本地开发 → Git → Vercel / Cloudflare 部署

1.4 动手实操（20min）

用 Bolt.new 搭建「电商数据查询小工具」，30 分钟内拿到可分享链接。

模块二：认识 Agentic Engineering（1.5h）

定位：从"我会用 AI"升级到"我理解 AI 协作的本质"。

2.1 从一个故事开始（15min）

真实案例：某团队用 AI 开发了 10 个内部工具，但 3 个月后 7 个已经无法维护。为什么？
答案：他们把 AI 当成"一次性代码生成器"，而不是"持续协作伙伴"。

2.2 核心定义

Agentic Engineering（智能体工程）：将非确定性 LLM 系统演化为可靠协作体系的工程学科。核心资产是知识（指令、技能、上下文），而非代码；演化方式是持续反馈驱动的改进，而非一次性版本发布。

2.3 与传统软件工程的根本差异

传统软件工程Agentic Engineering
核心资产是代码核心资产是知识（指令、技能、上下文）
质量靠单元测试 + CI质量靠场景验证 + 持续观测 + 反馈循环
演化方式是版本发布演化方式是 Signal 驱动的连续涌现
设计单元是模块/服务设计单元是 Agent + Skill + Instruction 的组合

2.4 三个交叉技能集

技能集你已经具备的需要学习的
产品思维理解业务场景、知道用户要什么如何把模糊需求转化为 AI 可执行的 spec
工程能力能写代码、会调试版本控制、可观测性、故障恢复
领域知识工程懂电商运营、懂数据如何把领域经验转化为 AI 可消费的知识

模块三：四层协作模型 — 你的 AI 协作体系（2h）

定位：从"个人使用 AI"升级到"建立 AI 协作体系"。

3.1 四层模型总览

治理层
复盘习惯、改进机制、知识管理 → 让能力持续进化
↕
协作层
Prompt 模板、Skill 文件、AI 协作流程 → 你和 AI 怎么配合
↕
工具层
Bolt.new、Cursor、API、数据源 → 用什么工具干活
↕
业务层
数据看板、客服 chatbot、直播话术助手 → 最终产出什么价值
核心洞察：问题总在业务层感知，根因总在上层。修复优先级：离业务最近的上层缺口优先。

3.2 电商场景映射

层电商场景中的含义举例
业务层你做的数据看板、客服 chatbot看板数据不准
协作层你的 prompt 模板、Skill 文件prompt 没写清楚数据口径
工具层Bolt.new、Cursor、API工具不支持直接从数据库拉数据
治理层你的复盘习惯、改进机制没人复盘为什么看板数据不准

3.3 层间归因练习（互动）

场景表面问题根因在哪层？
AI 生成的图表颜色太丑业务层协作层：prompt 没指定配色方案
同一个需求，AI 每次输出不一样业务层协作层 + 治理层：缺 Skill 标准化 + 缺质量检查机制
想做实时数据看板但 AI 说做不了业务层工具层：工具链不支持实时数据接入
团队 5 个人用 AI，效果参差不齐业务层治理层：没有统一 prompt 模板和培训

3.4 Skill 文件模板（实操）

# 直播数据看板开发 Skill

## 适用场景
当需要开发电商直播运营数据看板时使用。

## 数据口径约定
- GMV：含退款前金额
- 转化率：下单人数 / 观看人数
- 客单价：GMV / 下单人数

## 设计规范
- 配色：主色 #FF6B35（品牌橙），辅色 #004E89（深蓝）
- 图表库：Recharts
- 移动端适配：768px 断点

## 常见问题
- 数据为 0 时显示 "-" 而非 "0"
- 日期格式统一为 YYYY-MM-DD

5.1 什么是改进信号

定义：改进信号是"你的 AI 协作体系哪里不对劲"的早期线索。

层改进信号示例
业务层"看板加载太慢了"、"数据好像不对"
协作层"prompt 写太长了"、"AI 总误解我的意思"
工具层"这个工具不支持导出 Excel"、"API 又挂了"
治理层"团队没人知道怎么用这个工具"、"上次的 bug 又出现了"

5.2 两种改进信号

类型本质电商场景示例
问题型已经出了问题，需要修复看板数据口径错误，导致运营决策失误

7.1 能力锻造

形态是什么电商场景举例

团队规范始终生效的规则"所有运营数据看板必须支持 Excel 导出"

7.2 经验沉淀的复利效应

核心洞察：单次知识沉淀的价值随复用次数增长而指数放大。

第 1 次：花 2h 写 Skill → 节省后续 AI 协作 0.5h 摸索
第 5 次：累计节省 2.5h，ROI = 1.25
第 20 次：累计节省 10h，ROI = 5
第 100 次：累计节省 50h，ROI = 25

经验沉淀三问

  1. 这次工作产生了哪些稳定可复用的知识？（排除一次性操作日志）
  2. 沉淀到哪个层级最合适？（Skill / 规范 / Prompt 模板 / 团队 wiki）
  3. 下一个使用这条知识的场景是什么？（验证复用性）
